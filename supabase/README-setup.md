# Аналітика магазину конструкторів

Дашборд, який сам забирає замовлення з SalesDrive і рахує продажі, маржу, конверсію, оплати, окупність реклами і **чистий прибуток** після реклами, податків, зарплат та інших витрат.

**Усе працює онлайн.** Дані лежать у хмарі (Supabase), а дашборд — це сайт із власним посиланням (Netlify). Ви й бізнес-партнер заходите з будь-якого комп'ютера чи телефона під своїми логінами й бачите одні й ті самі цифри. Коли один із вас вносить витрату або змінює налаштування, у другого дашборд оновлюється сам, за секунду. На комп'ютері нічого не зберігається і нічого не треба тримати ввімкненим.

```
SalesDrive ──(кожні 15 хв)──► Supabase (хмара): синхронізація + база
                                        ▲                 ▲
                         https://ваш-сайт.netlify.app (дашборд)
                              │                     │
                            ви                 партнер
```

## Що в папці

| Файл | Що це |
|---|---|
| `dashboard/index.html` | Дашборд. Саме цю папку `dashboard` викладаєте в інтернет (крок 8) |
| `supabase/schema.sql` | Таблиці бази й аналітичні функції. Виконується один раз |
| `supabase/functions/constructor-sync/index.ts` | Функція, яка тягне замовлення з SalesDrive |
| `supabase/cron.sql` | Автозапуск синхронізації кожні 15 хвилин |
| `dashboard-src/` | Вихідні частини дашборду для майбутніх змін (викладати не треба) |

Відкрийте `dashboard/index.html` просто зараз, щоб подивитися: без підключення він показує демо-дані.

## Підключення: покроково (≈ 40 хвилин, один раз)

### 1. Новий проєкт Supabase
supabase.com → **New project**. Назва, наприклад, `constructor-analytics`, регіон **Central EU (Frankfurt)**. Збережіть пароль бази.

> Безкоштовний тариф дозволяє 2 проєкти. Якщо обидва вже зайняті, можна використати проєкт для одягу, але окремий надійніший, бо таблиці не змішуються.

### 2. Таблиці бази
**SQL Editor → New query** → вставте весь вміст `supabase/schema.sql` → **Run**. Повідомлення «Success» означає, що все створено.

### 3. API-ключ SalesDrive
У SalesDrive бази конструкторів: **Установки → Загальні налаштування і інтеграції → Інші сервіси → API → API-ключі → Створити API-ключ**. Достатньо права на читання заявок.

### 4. Функція синхронізації
**Edge Functions → Deploy a new function → Via Editor**.
- Назва: `constructor-sync` (саме так)
- Замініть шаблонний код вмістом `supabase/functions/constructor-sync/index.ts`
- **Deploy function**. Потім у налаштуваннях функції (вкладка **Details** або **Settings**) **вимкніть «Verify JWT with legacy secret»** / «Enforce JWT verification». Функція сама перевіряє, хто її викликає: користувач дашборду або автозапуск із секретом.

### 5. Секрети функції
**Edge Functions → Secrets → Add new secret**:

| Назва | Значення |
|---|---|
| `SALESDRIVE_DOMAIN` | піддомен вашої CRM: для `konstruktor.salesdrive.me` це `konstruktor` |
| `SALESDRIVE_API_KEY` | ключ із кроку 3 |
| `CRON_SECRET` | будь-який довгий набір літер і цифр, придумайте самі |
| `INITIAL_SYNC_FROM` | *(необов.)* з якої дати вантажити історію, напр. `2025-01-01`. За замовчуванням рік тому |
| `SALESDRIVE_SAJT` | *(необов.)* брати лише ці сайти (id через кому). Потрібно, тільки якщо в CRM є сайти, які взагалі не стосуються конструкторів |

Ключі зберігаються лише в Supabase. У дашборд і браузер вони не потрапляють.

### 6. Користувачі: ви і партнер
- **Authentication → Users → Add user → Create new user**: ваш email і пароль, увімкніть «Auto Confirm User».
- Так само створіть другого користувача для партнера (його email і пароль). Кожен входить під своїм логіном, а у витратах видно, хто що вніс.
- **Authentication → Sign In / Providers**: вимкніть **Allow new users to sign up**. Тоді ніхто сторонній не зможе зареєструватися й побачити дані.

### 7. Підключити дашборд
Потрібні дві речі: **адреса проєкту** і **publishable key**.
- Найпростіше: на головній сторінці проєкту натисніть кнопку **Connect** угорі. У вікні буде адреса (`https://xxxx.supabase.co`) і ключ.
- Або: **Project Settings** (шестерня внизу лівого меню) → **API Keys**. Скопіюйте **Publishable key** (починається з `sb_publishable_`). Якщо бачите лише старі ключі, підійде **anon public** (починається з `eyJ`) з вкладки «Legacy API keys».
- Адресу видно й у рядку браузера: у `supabase.com/dashboard/project/abcdxyz` адреса проєкту буде `https://abcdxyz.supabase.co`. Відкрийте `dashboard/index.html` у Блокноті або VS Code, знайдіть на початку скрипта:

```js
const CONFIG = {
  SUPABASE_URL: '',        // напр. 'https://abcdxyz.supabase.co'
  SUPABASE_ANON_KEY: '',   // довгий ключ, що починається з eyJ...
```

Вставте значення між лапками і збережіть. Publishable key можна тримати у файлі: без входу за паролем він нічого не відкриває. **Secret key / service_role у файл не вставляйте ніколи.**

### 8. Викласти дашборд в інтернет (Netlify, безкоштовно)
1. Відкрийте **app.netlify.com/drop** і зареєструйтеся (можна через Google).
2. Перетягніть у вікно папку `dashboard` (з уже заповненим CONFIG з кроку 7).
3. За кілька секунд отримаєте посилання на кшталт `https://random-name-123.netlify.app`.
4. **Site configuration → Change site name**: задайте зрозумілу адресу, напр. `konstruktor-analytics` → `https://konstruktor-analytics.netlify.app`.
5. Надішліть посилання партнерові разом із його логіном і паролем.

Щоб оновити дашборд у майбутньому (новий файл від мене): Netlify → ваш сайт → **Deploys** → перетягніть папку `dashboard` ще раз. Посилання не зміниться, дані теж.

> Замість Netlify можна використати Cloudflare Pages або GitHub Pages: принцип той самий, це просто хостинг для одного файлу.

### 9. Перший запуск
Відкрийте своє посилання, увійдіть і натисніть **Оновити дані**. Почнеться завантаження історії: за один запуск функція встигає ~1500 замовлень. Кожне натискання або автозапуск продовжує з того місця, де зупинилось. Прогрес видно внизу бічної панелі й у **Налаштуваннях**.

### 10. Автозапуск кожні 15 хвилин
- **Database → Extensions**: увімкніть `pg_cron` і `pg_net`.
- Відкрийте `supabase/cron.sql`, замініть `ВАШ_PROJECT_REF` і `ВАШ_CRON_SECRET` і виконайте в SQL Editor.

### 11. Налаштування в дашборді
- **Налаштування → Магазини**: кожен сайт із SalesDrive з’явиться тут сам (#номер сайту). Дайте магазинам назви, а зайві сайти вимкніть.
- **Налаштування → Статуси SalesDrive**: перевірте, що кожен статус віднесено правильно (Продаж / Відмова / Повернення / В роботі / Не враховувати) і які статуси позначені «Підтверджене». Від цього залежать усі цифри.
- **Налаштування → Менеджери**: імена, ставка за продаж, % від допродажів.
- **Налаштування → Основне**: курс долара, цілі ROMI, ціни продажу й конверсії.
- **Витрати → Автоматичні витрати**: єдиний податок (% від виручки), ЄСВ, підписки (сума на місяць), пакування (за продаж).
- **Витрати** або **Реклама**: вносьте рекламні витрати в $ чи ₴, за день або одразу за тиждень.

## Як зараховуються замовлення по днях
Кожне замовлення завжди належить дню, коли його створили в SalesDrive. Синхронізація кожні 15 хвилин забирає всі замовлення, змінені від минулого разу, хоч би якими старими вони були. Замовлення від 20-го, підтверджене 25-го, після оновлення з'явиться як підтверджене у 20-му числі. Так само відмова потрапить у 20-те. Тому цифри останніх днів ще «доростають», поки замовлення підтверджуються й викуповуються.

## Кілька магазинів
Кожен сайт у SalesDrive (поле «Сайт» у заявці) — окремий магазин.
- **Перемикач «Усі магазини / магазин 1 / магазин 2»** угорі кожної сторінки. Огляд, По днях, По місяцях, Товари, Реклама й Менеджери показують обраний магазин.
- **Сторінка «Магазини»**: порівняння поруч (виручка, прибуток, реклама, ROMI, конверсія), графік магазинів у динаміці й окрема картка загальних витрат.
- **Витрати й реклама** вносяться з вибором магазину або як «Загальна».
- **Загальні витрати** (без магазину) і загальні щомісячні правила (ЄСВ, CRM) не діляться між магазинами. Їх видно в «Усі магазини» і на сторінці «Магазини».
- **Загальні правила «% від виручки» і «за продаж»** (єдиний податок, пакування) кожен магазин рахує від своєї виручки й своїх продажів. Правило можна прив’язати й до одного магазину.

## WayForPay: фактична комісія
1. Supabase → Edge Functions → Deploy a new function → Via Editor → назва `wayforpay-sync` → код з `supabase/functions/wayforpay-sync/index.ts` → Deploy → вимкніть Verify JWT.
2. Edge Functions → Secrets: `WFP_MERCHANT_ACCOUNT` (Merchant login, напр. `mblok_shop`) і `WFP_SECRET_KEY` (Merchant secret key). Merchant password не потрібен.
3. Оновіть функцію `constructor-sync` новим кодом (вона тепер зберігає зовнішній номер заявки) і перезавантажте період з 01.09.
4. Витрати → блок WayForPay → «Оновити WayForPay». Далі щогодини автоматично (друга задача в `cron.sql`).

Комісія прив'язується до заявки за номером Tilda (друга частина номера WayForPay = «Зовнішній номер заявки» в SalesDrive), а якщо не вийшло — через вхідні платежі SalesDrive. Віднімається в день і в магазині замовлення, рядок «Комісія WayForPay».

## Спільна робота з партнером
- Кожен заходить за одним посиланням під своїм логіном, з комп'ютера чи телефона.
- Усі бачать ті самі дані: замовлення, витрати, правила, налаштування.
- Зміни видно одразу. Якщо партнер додав рекламу, у вас дашборд перерахується сам, і з'явиться повідомлення «Дані оновлено». Якщо ви саме заповнюєте форму, дашборд не перезавантажиться, а покаже кнопку «Оновити».
- У таблиці витрат є колонка «Вніс»: видно, хто додав кожен запис.
- Внизу бічної панелі напис «онлайн» означає, що зв'язок у реальному часі активний.
- Додати ще людину: Supabase → Authentication → Users → Add user. Забрати доступ: там же видалити користувача.

## Як рахуються показники

| Показник | Формула |
|---|---|
| Виручка | сума замовлень у статусах «Продаж» |
| Валовий прибуток | виручка − собівартість − доставка − комісії − витрати в замовленні − витрати на повернення |
| Чистий прибуток | валовий − реклама − ручні витрати − автоматичні правила − зарплата менеджерів (для окремого магазину без загальних витрат) |
| Підтверджені | заявки періоду, чий статус позначено галочкою «Підтверджене» (Налаштування → Статуси) |
| Не підтверджені | заявки «в роботі», ще не підтверджені (напр. «Новий», «Недодзвон») |
| Ціна підтвердженого | реклама / підтверджені |
| Конверсія | продажі / усі заявки, створені в періоді (без «Не враховувати») |
| ROMI | (валовий прибуток − реклама) / реклама |
| ДРР | реклама / виручка |
| Ціна продажу | реклама / кількість продажів |
| Викуп товару | продано / (продано + відмови + повернення) |

- Собівартість, доставка і комісії беруться з полів замовлення SalesDrive, тому їх важливо заповнювати в CRM.
- Канал реклами визначається за UTM-міткою замовлення: facebook/instagram → Meta, google → Google, tiktok → TikTok, sms/viber → Розсилки.
- Допродаж — товари, позначені в SalesDrive як «допродаж» (preSale).

## Якщо щось не працює
- **«Потрібно увійти в дашборд»** при синхронізації: вийдіть і увійдіть знову.
- **«Не задано секрети…»**: перевірте крок 5 і назви секретів.
- **«SalesDrive: api key is invalid»**: ключ скопійовано не повністю або в нього немає права читання заявок.
- Історія пишеться як «завантажується» довго: SalesDrive дозволяє 100 запитів на годину. 10 000 замовлень завантажаться приблизно за 1,5–2 години. Автозапуск продовжить сам.
- Журнал запусків: **Налаштування** в дашборді або `select * from sync_log order by id desc;` у SQL Editor.
